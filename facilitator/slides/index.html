THE PROBLEM

Vibe coding builds a house of cards

04 / 25

01

AI writes code faster than teams make decisions.

02

Agents remember nothing between sessions.

03

Every assumption that is not written down is renegotiated — or hallucinated — on the next prompt.

Ad-hoc prompting gives plausible code in minutes and unmaintainable debt in hours. The problem is not the model; it is the missing record of decisions.

SPECIFICATION-FIRST

The 95 / 5 shift

05 / 25

95 %

understand the problem, decide, make it verifiable

5 %

implementation by the AI

When the specification is complete, code becomes a disposable build artifact.
Ninety-five percent of the work is understanding, deciding and making it verifiable. The AI does the last five percent — and then the code is something you can throw away and rebuild.

THREE ARTIFACTS

The specification triad

06 / 25
Register Question Where
ADR — Architecture Decision Record Why? governance/adr/
LIM — Limitation Record Where not (yet)? governance/limitations/
Feature file + black-box steps What, observably? bdd/
ADRs, LIMs and feature files are plain Markdown and Gherkin; the small Python steps only run the features against the system. One agent can read the whole specification in one context window.
Three registers, all text: why (ADR), where not yet (LIM), what (feature file plus black-box steps). Small enough that one agent reads all of it at once.

WORKFLOW

Five phases, one rule

07 / 25
1. Decide → ADRs, LIMs
2. Error paths, then feature files ■ RED
3. Specification critic ◎ AUDITED
4. Black-box steps + honesty audit ◆ STILL RED
5. Autonomous implementation, any language ▲ GREEN
Feedback loop rule: a gap the critic, the audit or reality finds changes the ADR, LIM or feature file first — never the code directly. A failing scenario is just a bug: fix the code.
Today you walk through phases 1, 2, 3 and 5. Phase 4 is the bonus. Make the distinction explicit: a gap in the specification goes back to ADR, LIM or feature file; code that fails an existing scenario is simply fixed — that is what the agent does in exercise 4.

A LIM tells the next agent what not to "fix".

TOLERANCE BOUNDS

The tolerance rows bound the rule: a tolerance below half of 1e-9° or from twice of it no longer turns green. They narrow the range — they do not prove the exact value.

From exercise 3 on, everybody works on the reference decision.
Three minutes. Ask: why do the eastern points fail? Then explain the tolerance rows: half the tolerance must be inside, twice must be outside — a bounded range, not proof of the exact value; that is what GREEN can and cannot tell you. SUMMARY

Take home
